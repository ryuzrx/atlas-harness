name: user-stories
description: Write user stories with acceptance criteria.
---

Use this to write user stories that can be built and tested.

## Steps
1. Format: "As a <type of user>, I want <capability> so that <benefit>."
2. Keep each story small enough to finish in a few days and valuable on its own. Split by workflow step, rule or data type if it's too big.
3. Add acceptance criteria as Given / When / Then, covering the happy path, edge cases and errors.
4. Note what's out of scope and any open questions.
5. Check the story against INVEST: independent, negotiable, valuable, estimable, small, testable.

## Output
The story, its acceptance criteria, notes on what's out of scope, and open questions.
