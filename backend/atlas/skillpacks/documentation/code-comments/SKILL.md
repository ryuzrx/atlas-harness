Use this to write helpful code comments.

## Steps
1. Comment *why*, not *what*: the intent, constraints, trade-offs, and links to bugs or specs.
2. Write doc comments on public functions: what it does, its parameters, returns, errors and an example if it's not obvious.
3. Flag anything surprising: workarounds, performance hacks, security-sensitive code.
4. Delete comments that just repeat the code, or that are now wrong.
5. Prefer clearer names and smaller functions to explaining tangled code.

## Output
The code with improved comments, and a note on any comments you removed.
