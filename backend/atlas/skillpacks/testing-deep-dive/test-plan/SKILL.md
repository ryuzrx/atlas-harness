Use this to write a test plan.

## Steps
1. Scope: what's being tested, what isn't, and the build or version.
2. Risks: which areas are most likely to break or would hurt most. Focus effort there.
3. Approach: which kinds of test (unit, integration, end-to-end, manual exploratory, performance, security, accessibility) and who does them.
4. Test cases for each feature: the happy path, edge cases, errors, and different roles and devices.
5. Environment and data needed.
6. Entry and exit criteria: what must pass before release.

## Output
The test plan document, with a test-case table.
